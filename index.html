PATH 01 · FOUNDATION

Azure 系統管理員的先決條件Administrator prerequisites

從日常管理工具到基礎架構部署，補齊進入 Azure 系統管理工作的必要起點。

01.01

Azure Cloud Shell 簡介Introduction to Azure Cloud Shell

認識瀏覽器中的命令列環境，了解如何使用 Azure CLI 或 PowerShell 管理 Azure。

01.01 · STUDY NOTES

免安裝、已驗證的 Azure 終端機A ready-to-use, authenticated Azure terminal

Azure Cloud Shell 是從瀏覽器使用的互動式終端機，可直接管理 Azure 資源。它由 Microsoft 管理環境，登入後會使用目前帳戶的 Azure 認證，常見入口包括 Azure 入口網站和 shell.azure.com。

Azure Cloud Shell is an interactive browser-based terminal for managing Azure resources. Microsoft manages the environment, and your signed-in account supplies the Azure context. Common entry points include the Azure portal and shell.azure.com.

01 / CHOOSE YOUR SHELL

Bash 或 PowerShellPick the command-line experience

Bash 適合 Linux shell 與 Azure CLI 工作流程；PowerShell 適合 PowerShell 語法與 Azure PowerShell 模組。兩者都能呼叫 Azure 管理介面，但指令名稱、參數和腳本語法不同，不能把 `az` 命令直接當成 `Get-Az*` 命令。

Use Bash for shell and Azure CLI workflows, or PowerShell for PowerShell syntax and Azure PowerShell cmdlets. Both can manage Azure, but their commands and scripting syntax differ.

02 / SESSION & STORAGE

工作環境暫存，檔案可持續Temporary host, persistent files

Cloud Shell 主機依工作階段建立；閒置 20 分鐘後工作階段會逾時。掛載的 Azure Files 檔案共用會把檔案保存在 `$HOME`，可供後續工作階段使用。不要把唯一副本放在暫存目錄；Cloud Shell 主機免費，但關聯儲存體仍會產生一般 Azure 儲存費用。

The Cloud Shell host is session-based and times out after 20 minutes of inactivity. A mounted Azure Files share persists files in `$HOME` across sessions. Avoid keeping the only copy in temporary locations. The host is free; normal Azure Storage charges still apply.

03 / CHECK THE CONTEXT

確認目前操作的訂用帳戶Verify the active subscription

登入後先確認命令實際使用的租用戶與訂用帳戶，避免把資源部署到錯誤環境。Azure CLI 可用 `az account show` 檢查目前內容，再用 `az account set --subscription` 切換；Azure PowerShell 則可用 `Get-AzContext` 與 `Set-AzContext`。

Before changing resources, verify the active tenant and subscription. Use `az account show` and `az account set --subscription` with Azure CLI, or `Get-AzContext` and `Set-AzContext` with Azure PowerShell.

AZ-104 · EXAM FOCUS

考題會測「選擇工具與工作階段」Expect tool and session scenarios

  • 辨識 Cloud Shell 可使用 Bash 或 PowerShell，以及可從哪些入口啟動。
  • 分辨 Cloud Shell 的暫存主機與 Azure Files 中持續保存的 `$HOME` 檔案。
  • 判讀指令目前使用的帳戶/訂用帳戶，避免在錯誤範圍執行管理工作。

Be ready to choose Bash or PowerShell, identify where session files persist, and verify which Azure account or subscription a command will affect.

PATH 02 · IDENTITY & GOVERNANCE

管理身分識別和治理Manage identities and governance

從 Microsoft Entra 身分開始，延伸到資源存取、政策與訂用帳戶治理。

02.01

了解 Microsoft Entra IDUnderstand Microsoft Entra ID

認識 Azure 雲端身分識別服務，以及目錄、使用者和群組的基本概念。

02.01 · STUDY NOTES

先分清楚身分目錄與網域服務Understand the identity directory and domain services

Microsoft Entra ID 是雲端式身分識別與存取管理服務。每個組織的 Entra 租用戶都是獨立的目錄邊界，保存並管理使用者、群組、應用程式及其他身分物件，支援雲端應用程式的驗證與存取控制。

Microsoft Entra ID is a cloud identity and access management service. Each organization's Entra tenant is a separate directory boundary for users, groups, applications, and other identities, supporting authentication and access control for cloud applications.

CORE CONCEPT · AUTHENTICATION ≠ AUTHORIZATION

先驗明身分，再判斷權限Prove identity, then evaluate access

驗證（authentication）回答「你是誰」；授權（authorization）回答「你能做什麼」。Entra ID 驗證身分並套用相關存取條件；Azure RBAC 則將 Azure 資源操作權授予安全性主體。登入成功不代表自動擁有訂用帳戶或資源的管理權。

Authentication establishes who you are; authorization determines what you can do. A successful sign-in alone does not grant Azure resource permissions.

DIRECTORY OBJECTS

租用戶是目錄邊界The tenant is the directory boundary

常見目錄物件包含使用者與群組，也包含應用程式相關身分。組織成員通常以成員使用者管理；合作夥伴或來賓可透過外部身分協作。群組可簡化對使用者集合的管理，但群組成員資格與 Azure 資源角色指派仍是不同設定。

Common directory objects include users, groups, and application identities. Members represent people in the organization; guests support external collaboration. Group membership and Azure resource role assignments are separate configurations.

EXAM DISTINCTION

Entra ID、AD DS、Entra Domain ServicesKnow which directory service fits the scenario

服務 / Service主要用途 / What it provides題目線索 / Scenario clue
Microsoft Entra ID雲端身分目錄、雲端應用程式驗證與存取管理。Cloud identity directory, authentication, and access management.雲端登入、租用戶、使用者/群組、應用程式存取。Cloud sign-in, tenant, users/groups, app access.
Active Directory Domain Services (AD DS)傳統網域控制站與網域服務，例如 LDAP、Kerberos/NTLM、網域加入與群組原則。Traditional domain controllers, LDAP, Kerberos/NTLM, domain join, and Group Policy.內部部署 Windows 網域或既有傳統網域工作負載。On-premises Windows domain or legacy domain workloads.
Microsoft Entra Domain Services由 Azure 管理的網域服務，提供相容的 LDAP、Kerberos/NTLM 與群組原則能力。Azure-managed domain services with compatible LDAP, Kerberos/NTLM, and Group Policy capabilities.雲端中的舊版應用程式需要網域功能，但不想自行維護網域控制站。Cloud legacy apps need domain features without self-managing domain controllers.

LICENSING SNAPSHOT

Free、P1、P2 的常見辨識Recognize common license differences

Free 提供基本目錄與身分功能；P1 包含條件式存取等進階存取控制；P2 再涵蓋風險型條件式存取、Identity Protection 與 Privileged Identity Management（PIM）等能力。實際功能與授權包裝會調整，部署時應查最新授權文件。

Free covers core directory capabilities; P1 includes features such as Conditional Access; P2 adds capabilities such as risk-based Conditional Access, Identity Protection, and PIM. Verify current licensing before deployment.

AZ-104 · EXAM FOCUS

把觀念連到身分管理工作Connect concepts to administrator tasks

  • 理解 Microsoft Entra ID 與 AD DS 的用途差異，也要辨識何時需要 Entra Domain Services。
  • 知道使用者、群組、外部使用者、授權與自助式密碼重設屬於身分管理範圍。
  • AZ-104 的「管理 Azure 身分識別與治理」整體占 20–25%；考綱還包含 Azure RBAC、Policy、訂用帳戶及治理，不只測 Entra ID 概念。

Distinguish Entra ID from AD DS and Entra Domain Services. The broader 20–25% identity and governance domain also covers users, groups, external users, licensing, SSPR, RBAC, policy, subscriptions, and governance.

02.03 · STUDY NOTES

RBAC 與權限範圍Role assignments and scope

RBAC 不只是選一個角色；你同時決定「誰」可以做「什麼」，以及權限套用「在哪裡」。

01

安全性主體 WHO

被授權的身分，例如使用者、群組、服務主體或受控識別。

The identity receiving access: a user, group, service principal, or managed identity.

PRINCIPAL
02

角色定義 WHAT

一組允許的操作。Reader 可檢視資源；Contributor 可管理資源，但不能指派 Azure RBAC 角色。

A set of allowed actions. Reader can view resources; Contributor can manage resources but cannot assign Azure RBAC roles.

ROLE
03

範圍 WHERE

角色生效的資源邊界。由管理群組、訂用帳戶、資源群組到個別資源，子範圍會繼承上層指派。

The boundary where the role applies. Child scopes inherit assignments from management groups, subscriptions, resource groups, and resources.

SCOPE

SCOPE HIERARCHY

範圍越上層，
影響越廣。

在上層範圍授予的權限會向下繼承。只想管理一個資源群組，就不必把角色指派在整個訂用帳戶。

Assignments flow down to child scopes. If access is needed for one resource group, there is no need to grant it at the subscription level.

考點辨析　Azure RBAC 管理「誰能對 Azure 資源做什麼」；Azure Policy 管理資源應符合的規則與設定。兩者目的不同。

Exam distinction　Azure RBAC controls who can do what to Azure resources. Azure Policy enforces rules and configuration requirements. They solve different problems.
